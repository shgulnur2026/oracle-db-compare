# Техническое задание: сравнение таблиц территориальных БД Oracle с республиканской БД

## 1. Цель

Проверить, что записи таблиц территориальных баз данных (БД) присутствуют в республиканской БД и что в республиканской БД у найденных записей заполнено поле `BlobArch`. Записи, не прошедшие проверку, выгрузить для анализа: сначала списком ключей в текстовый файл, затем полными записями в отдельную таблицу и файл дампа Oracle.

Решение: веб-страница (локальное веб-приложение), на которой вводятся параметры подключения, расположение файлов и запускается процесс.

## 2. Исходные данные и условия

- СУБД: Oracle. Баз данных несколько: одна республиканская и территориальные (на текущий момент три, в перспективе 275).
- В каждой БД есть таблица, структура таблиц во всех БД одинакова.
- Первичный ключ таблицы составной: поля `ID` и `KNR`.
- Проверяемое поле в республиканской БД: `BlobArch`.
- Подключение к каждой БД выполняется с указанием схемы.

## 3. Термины

| Термин | Значение |
|---|---|
| Территориальная БД | БД района или области, источник проверяемых записей |
| Республиканская БД | БД, с которой сравнивается содержимое территориальных |
| Район/область | Название территории, по которому различаются файлы и строки результата |
| Этап 1 | Сравнение территориальной БД с республиканской |
| Этап 2 | Выгрузка найденных записей в таблицу ANL и дамп |
| Таблица ANL | Таблица в территориальной БД с именем «имя исходной таблицы + `ANL`» |

## 4. Общие требования к приложению

1. Работает как веб-страница: сервер запускается на компьютере пользователя (`python app.py`) и доступен по адресу `http://127.0.0.1:8765`. Сервер слушает только локальный адрес.
2. Технологии: Python, драйвер `oracledb` (клиент Oracle не требуется), `openpyxl` для чтения и создания Excel-файлов.
3. Пароли вводятся на странице, нигде не сохраняются и не пишутся в лог. Остальные поля формы запоминаются браузером для следующего запуска.
4. Во время работы на странице в реальном времени отображается лог, есть кнопка «Остановить».
5. Все имена объектов Oracle (схемы, таблицы, поля, каталог) проверяются на допустимые символы до начала работы.

## 5. Параметры, вводимые на странице

### 5.1. Режим работы

- **Этап:** 1 (сравнение) или 2 (таблицы ANL и дамп).
- **Подключение:** одна территориальная БД или множество БД из внешнего Excel-файла.

### 5.2. Подключения

Для каждого подключения: хост, порт, имя службы (service name), пользователь, схема, пароль.

- Республиканская БД: обязательна на этапе 1, на этапе 2 не используется.
- Территориальная БД (режим «одна»): те же поля плюс обязательное поле **«Район/область»**.

### 5.3. Что обрабатывать

- Список таблиц (через запятую или с новой строки).
- Названия полей первичного ключа: по умолчанию `ID` и `KNR`.
- Поле для проверки: по умолчанию `BlobArch`.

### 5.4. Файлы

- Папка результатов на компьютере пользователя (создаётся при необходимости).
- Имя файла результата (по умолчанию `compare_result.txt`).
- Имя файла лога (по умолчанию `compare_log.log`).
- Имя файла сводки по всем базам (по умолчанию `compare_summary.txt`), только для режима «множество БД».

## 5.5. Параметры этапа 2

- Каталог Oracle (`DIRECTORY`) на сервере БД, куда записывается дамп.
- Имя файла дампа (по умолчанию `compare_anl.dmp`).
- Флаг «Пересоздавать существующие таблицы ANL» (по умолчанию выключен).

## 6. Режим «множество БД» (Excel)

1. Параметры подключения и район/область берутся из внешнего файла `.xlsx` или `.csv`, путь к которому указывает пользователь.
2. Первая строка файла содержит заголовки. Столбцы:

   | Столбец | Обязателен | Примечание |
   |---|---|---|
   | Район/область | да | Допустимые синонимы: Район, Область, Регион, Region |
   | Хост | да | |
   | Порт | нет | По умолчанию значение со страницы, иначе 1521 |
   | Служба | да | |
   | Пользователь | нет | Если пусто, берётся значение со страницы |
   | Схема | нет | Если пусто, берётся значение со страницы |
   | Пароль | нет | Если пусто, берётся значение со страницы |

3. Шаблон Excel-файла скачивается по ссылке на странице.
4. Пустые строки пропускаются. Ошибки в файле (незаполненное обязательное поле, повтор района) выдаются до запуска с указанием номера строки.
5. Район/область должен быть уникальным: от него зависят имена файлов.
6. Базы обрабатываются параллельно, число потоков задаётся на странице (по умолчанию 4, максимум 32). Недоступность одной базы не останавливает остальные.
7. Республиканская БД одна для всех территорий.

## 7. Этап 1: сравнение

Для каждой записи каждой указанной таблицы территориальной БД выполняется проверка в республиканской БД:

| Условие | Результат |
|---|---|
| Запись с таким же `ID` и `KNR` не найдена в республиканской БД | Строка в файл результата с причиной «не найдено в республиканской БД» |
| Запись найдена, поле `BlobArch` пустое (`NULL` или нулевая длина) | Строка в файл результата с причиной «поле BlobArch пустое в республиканской БД» |
| Запись найдена, `BlobArch` заполнено | Запись только учитывается в итогах |

Требования:
- В файл результата выгружаются только первичные ключи территориальной записи и причина выгрузки, а не вся строка.
- Проверка по ключам выполняется порциями (по 500 ключей за запрос). Содержимое `BlobArch` не читается, проверяется только его длина.
- После обработки всех записей файлы результата и лога сохраняются, процесс завершается.

### 7.1. Формат файла результата

Текстовый файл в кодировке UTF-8, разделитель полей `|`. Перед данными стоит строка заголовка, начинающаяся с `#`.

```
# REGION|TABLE|ID|KNR|REASON
Алматы|ТАБЛИЦА|101|5|не найдено в республиканской БД
Алматы|ТАБЛИЦА|102|7|поле BlobArch пустое в республиканской БД
```

Названия столбцов `ID` и `KNR` берутся из заданных названий полей ключа.

### 7.2. Именование файлов

К именам файла результата и лога добавляется район/область: `compare_result_<район>.txt`, `compare_log_<район>.log`. Для каждого района создаются отдельные файлы.

## 8. Этап 2: таблицы ANL и дамп

Выполняется отдельным запуском после этапа 1. Для каждого района:

1. Из файла результата этапа 1 читаются все первичные ключи по каждой таблице (повторы удаляются). Типы значений ключей приводятся к типам полей таблицы (число, дата, строка).
2. Подключение к территориальной БД. В той же схеме создаётся таблица с именем «имя таблицы + `ANL`» (например, `TABLE1ANL`) с той же структурой, что и исходная.
3. В таблицу ANL копируются все поля тех записей исходной таблицы, чьи ключи есть в файле. Запрос строится по всем ключам файла района; из-за ограничения Oracle на длину списка выполняется порциями по 500 ключей, но результат собирается в одной таблице.
4. Если таблица ANL уже существует: без флага пересоздания таблица пропускается с ошибкой в логе, с флагом старая таблица удаляется и создаётся заново.
5. Созданные таблицы ANL экспортируются в один файл дампа Oracle Data Pump (через пакет `DBMS_DATAPUMP`). Файл создаётся на сервере БД в каталоге `DIRECTORY`, заданном на странице.
6. Имя файла дампа: заданное имя плюс район латиницей (например, `compare_anl_shymkent.dmp`); рядом создаётся лог экспорта Data Pump.
7. На этом обработка района завершается.

При одной сравниваемой таблице на район создаётся одна таблица ANL и один дамп. Если указано несколько таблиц, для каждой создаётся своя таблица ANL (структуры таблиц различаются), все они попадают в один дамп района.

Лог этапа 2 сохраняется отдельно: `compare_log_anl_<район>.log`, чтобы не затереть лог этапа 1.

## 9. Логирование и итоги

- Для каждой территории ведётся отдельный лог-файл: подключения, обработка таблиц, каждая найденная проблемная запись (на этапе 1), ошибки, итоги по таблицам. Одновременно лог показывается на странице.
- На странице отображается таблица по районам: статус и числовые итоги.
  - Этап 1: записей, не найдено, `BlobArch` пуст, без замечаний.
  - Этап 2: ключей в файле, скопировано в ANL, не найдено в БД, таблиц ANL.
- В режиме «множество БД» в конце сохраняется файл сводки (`|`-разделитель) с итогами по каждому району и путями к его файлам; на этапе 2 к имени добавляется `_anl`.
- Статусы района: «завершено», «завершено с ошибками (N)», «остановлено», «ошибка», «пропущено (остановлено)».

## 10. Обработка ошибок

- Ошибка подключения к территориальной БД фиксируется в логе и итогах, остальные базы обрабатываются.
- Ошибка по одной таблице (таблица или поле не найдены, ошибка Oracle) не прерывает обработку остальных таблиц.
- Кнопка «Остановить» прекращает обработку после текущей порции данных; не начатые базы пропускаются.
- Недостающие права (создание таблицы, доступ к каталогу `DIRECTORY`) приводят к ошибке с текстом Oracle в логе и итогах.

## 11. Нефункциональные требования

- Производительность: данные читаются и сравниваются порциями; для больших таблиц используется потоковое чтение. Для 275 баз предусмотрена параллельная обработка.
- Надёжность: у каждого района собственные подключения и собственные файлы, сбой одной базы не влияет на другие.
- Безопасность: сервер доступен только локально; пароли не сохраняются; имена объектов Oracle проверяются.
- Переносимость: Windows и Linux, Python 3, зависимости `oracledb` и `openpyxl`.

## 12. Ограничения и допущения

1. «Пустое» поле `BlobArch` означает `NULL` или нулевую длину.
2. Таблицы ANL создаются в территориальной БД, в схеме, указанной для подключения.
3. Файл дампа создаётся на сервере территориальной БД, а не на компьютере пользователя; пользователю нужны права `CREATE TABLE` и `READ`/`WRITE` на каталог `DIRECTORY`.
4. Содержимое файла результата этапа 1 используется как входные данные этапа 2, поэтому в обоих запусках должны совпадать папка, имя файла результата, список таблиц и район.
5. Имя таблицы ANL (исходное имя + `ANL`) не должно превышать допустимую длину идентификатора Oracle.
6. Копирование записей с полями типа `LONG` в таблицу ANL может быть невозможно; такая ошибка фиксируется в логе.

## 13. Критерии приёмки

1. Страница позволяет ввести параметры подключения к республиканской и территориальной БД с указанием схем, список таблиц, район/область, папку и имена файлов, и запустить процесс.
2. Для записи, отсутствующей в республиканской БД по паре `ID`+`KNR`, в файле результата появляется строка с ключами и причиной «не найдено».
3. Для записи, найденной в республиканской БД с пустым `BlobArch`, в файле результата появляется строка с ключами и причиной «пустое».
4. Для записи с заполненным `BlobArch` в файл результата ничего не пишется.
5. Файлы результата и лога разных районов различаются по имени, а строки результата содержат район.
6. В режиме «множество БД» параметры и район читаются из указанного Excel-файла; недоступная база не останавливает остальные; формируется файл сводки.
7. На этапе 2 для района создаётся таблица «имя таблицы + `ANL`» со всеми записями, найденными по ключам из файла района, и экспортируется в файл дампа в каталоге `DIRECTORY`.
8. После завершения обработки файлы результата и лога сохранены, процесс завершён.

## 14. Вопросы для уточнения

1. Нужно ли сравнивать, помимо наличия `BlobArch`, его содержимое с территориальным значением (сейчас проверяется только заполненность)?
2. Нужно ли переносить файл дампа с сервера БД на компьютер пользователя автоматически (сейчас дамп остаётся на сервере)?
3. Нужен ли повторный запуск только для баз, закончившихся ошибкой?
